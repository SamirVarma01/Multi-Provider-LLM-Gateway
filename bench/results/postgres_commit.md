# Postgres commit latency

Generated by `scripts/pg_commit_latency.sh` on 2026-11-09T14:05:13Z at commit `5b8bab0`. Host: Apple M2, Darwin; Docker VM: 8 CPUs, 3.8 GiB memory. postgres (PostgreSQL) 17.11.

This measures Postgres alone, in the benchmark stack's container, with `pgbench`. The gateway is not involved.
Every request through the gateway updates its key's account row twice, once to reserve and once to settle,
and each update holds the row's lock until its commit is durable. These numbers bound what one key can do on this machine.

| `on` | 60484 | 1.5 | 3.3 | 4.9 | 18.1 | 41.8 | 0 |
| `off` | 59917 | 1.4 | 3.6 | 5.6 | 11.6 | 21.2 | 0 |

With `on`, the default and what the gateway uses, a commit waits until the WAL is flushed to disk. With `off`, it does not.
Any difference in the tail is the time the disk took to flush.
